Section 07 · The Software

Arduino Firmware

Toolchain setup, a walk through the base sketch, and the calibration ritual that turns eight imperfectly-centred servos into a usable robot.

Toolchain Setup

The base firmware uses the Arduino IDE and the built-in Servo library — nothing exotic. If you've blinked an LED on an Arduino before, you already have everything you need.

Installing the IDE

  1. Download the Arduino IDE 2.x

    From arduino.cc/en/software. Version 2.3 or newer is what we developed against. The legacy 1.8.x will compile the sketch but lacks the serial plotter improvements you'll want for calibration.

  2. Add the AVR board package

    Tools → Board → Boards Manager → search "Arduino AVR Boards" → Install. This bundles the toolchain for the ATmega328P on the Nano. Wait for it to finish before continuing.

  3. Select the board and processor

    Tools → Board → Arduino AVR Boards → Arduino Nano. Then Tools → Processor → ATmega328P (Old Bootloader) if your kit Nano was supplied as a clone (most of ours are); otherwise ATmega328P. If uploads fail with an avrdude timeout, swap between the two — that's almost always the fix.

  4. Plug in the Nano, identify the serial port

    Connect the USB-C cable. Tools → Port should now show a new entry — /dev/cu.usbserial-* on macOS, COM# on Windows, /dev/ttyUSB# on Linux. Select it. If nothing appears, see the USB cable warning in §02.

  5. Verify with Blink

    File → Examples → 01.Basics → Blink. Upload it. The Nano's onboard LED (next to D13) should start blinking at 1 Hz. If this works, your toolchain is good. If it doesn't, fix toolchain issues now — not during the more complex sketch.

Libraries

The base firmware uses only one external library, and it ships with the IDE — no additional install needed:

  • ServoBuilt-in
  • Other depsNone

If you find a library install dialog asking permission to fetch something, the sketch you have isn't ours. Check the repository for quadruped_base.ino.

Sketch Structure

The base sketch is intentionally minimal — it does exactly what the manual promises (stand, walk, button-stop, individual servo command via serial) and nothing more. Open quadruped_base.ino and follow along.

Servo Array Declaration

#include <Servo.h>

// Eight servos, one Servo object each, addressed by index 0..7.
// Index matches the channel map from §05:
// 0=FL-H, 1=FL-K, 2=FR-H, 3=FR-K,
// 4=BL-H, 5=BL-K, 6=BR-H, 7=BR-K
Servo legs[8];

// Pin assignments: D2..D9
const uint8_t SERVO_PIN[8] = { 2, 3, 4, 5, 6, 7, 8, 9 };

// Per-servo trim offsets, in degrees. Set during calibration.
// Positive trim shifts the neutral angle clockwise from 90°.
int8_t TRIM[8] = { 0, 0, 0, 0, 0, 0, 0, 0 };

const uint8_t LED_PIN = 10;
const uint8_t BTN_PIN = 11;

Three things to notice: (1) we hold the eight servos in a flat array indexed by the channel map; (2) the pin numbers are pulled into a const array so the index-to-pin mapping is in one place; (3) the TRIM array is the only thing you'll edit per-unit — every robot will have slightly different values, derived from calibration.

Setup

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  pinMode(BTN_PIN, INPUT_PULLUP);

  // Attach all eight servos and drive them to neutral immediately.
  // The 600/2400 µs range covers the SG90's full mechanical sweep
  // more reliably than the library default (544/2400).
  for (uint8_t i = 0; i < 8; i++) {
    legs[i].attach(SERVO_PIN[i], 600, 2400);
    legs[i].write(90 + TRIM[i]);
  }

  digitalWrite(LED_PIN, HIGH);   // ready
  Serial.println(F("Quadruped ready. Send 'h' for help."));
}

The servos are attached one by one and written to their trimmed neutral immediately. This is what produces the "stand up within two seconds" behaviour described in §01. The status LED comes on once setup completes — a useful signal that boot succeeded.

Note · Why 600 / 2400 µs?

The Servo library defaults to 544–2400 µs which works for most servos but pushes the SG90 past its mechanical end-stops on the low end — you'll hear it buzz unhappily. Restricting to 600–2400 keeps it inside the safe range. If your particular servo batch behaves differently, adjust by 50 µs at a time and observe.

Neutral Pose

// Drive all servos to their trimmed centre.
// Use this between gait cycles, on stop, and at boot.
void poseNeutral() {
  for (uint8_t i = 0; i < 8; i++) {
    legs[i].write(90 + TRIM[i]);
  }
}

// Write a specific angle to one servo, clamped to safe range.
void setServo(uint8_t idx, int angle) {
  if (idx >= 8) return;
  int a = constrain(angle + TRIM[idx], 10, 170);
  legs[idx].write(a);
}

Every angle you write goes through setServo(), which adds the trim and clamps to the safe range. Never call legs[i].write() directly outside of setup() — you'll bypass the trim and the clamp, and you'll learn an expensive lesson about servo mechanical limits.

A Minimal Gait

// A simple "creep" gait. Lifts one leg at a time, swings it
// forward, lowers it, then shifts weight onto the new contact.
// This is not graceful — it is honest about its mechanical limits.
//
// Each "frame" defines the eight angles, with delays between frames.
// Indices: 0=FL-H 1=FL-K 2=FR-H 3=FR-K 4=BL-H 5=BL-K 6=BR-H 7=BR-K

const uint16_t FRAME_MS = 180;

void stepCreepForward() {
  // Phase 1: lift FL knee, swing FL hip forward
  setServo(1, 60);  delay(80);
  setServo(0, 60);  delay(FRAME_MS);
  setServo(1, 90);  delay(80);

  // Phase 2: lift BR knee, swing BR hip forward
  setServo(7, 60);  delay(80);
  setServo(6, 120); delay(FRAME_MS);
  setServo(7, 90);  delay(80);

  // Phase 3: lift FR knee, swing FR hip forward
  setServo(3, 60);  delay(80);
  setServo(2, 120); delay(FRAME_MS);
  setServo(3, 90);  delay(80);

  // Phase 4: lift BL knee, swing BL hip forward
  setServo(5, 60);  delay(80);
  setServo(4, 60);  delay(FRAME_MS);
  setServo(5, 90);  delay(80);

  // Re-centre hips: body has now shifted forward
  setServo(0, 90); setServo(2, 90);
  setServo(4, 90); setServo(6, 90);
  delay(FRAME_MS);
}

The gait above is deliberately the simplest thing that works — one leg moves at a time, every leg returns to neutral between phases, no two legs are ever in the air simultaneously. It looks slow and ungainly because it is. The interesting gait work is reserved for the on-ground programme.

Main Loop

enum State { S_IDLE, S_WALKING };
State state = S_IDLE;
bool lastBtn = HIGH;

void loop() {
  // Button: toggle walking on/off (with debounce on edge)
  bool b = digitalRead(BTN_PIN);
  if (lastBtn == HIGH && b == LOW) {
    state = (state == S_IDLE) ? S_WALKING : S_IDLE;
    poseNeutral();
    digitalWrite(LED_PIN, state == S_WALKING ? LOW : HIGH);
    Serial.print(F("State: "));
    Serial.println(state == S_WALKING ? F("WALKING") : F("IDLE"));
    delay(60);  // debounce
  }
  lastBtn = b;

  // Serial commands for individual servo testing.
  // Format: "s <idx> <angle>\n" — e.g. "s 0 45"
  if (Serial.available()) {
    handleSerialCommand();
  }

  // Action
  if (state == S_WALKING) {
    stepCreepForward();
  }
}

The button on D11 toggles between idle and walking. The serial monitor lets you address any servo individually for calibration. The status LED on D10 is on when idle, off when walking — a passive heartbeat.

Tip · Read the serial output during early tests

Tools → Serial Monitor at 115200 baud. The sketch prints state transitions and acknowledges every s command. If you're getting unexpected behaviour, the serial output is usually the fastest path to understanding why.

Uploading to the Robot

  1. Open quadruped_base.ino in the IDE

    From the project repository — clone or download the zip. Open the .ino file; the IDE will offer to create a folder for it. Accept.

  2. Verify (Ctrl/⌘ + R)

    The compile step. Expect about ten seconds. Confirm the output reads "Sketch uses X bytes of program storage..." with no errors. Warnings are fine; errors must be fixed.

  3. Upload (Ctrl/⌘ + U)

    Disconnect the battery first. The Nano is powered through USB during upload; if both are connected and the buck is uncalibrated, you'll get a spike on the 5 V rail when the USB enumerates. After confirming the battery is unplugged, hit upload. Watch the Nano's TX/RX LEDs flicker as the bootloader receives the image.

  4. Confirm boot

    The status LED (D1 on the PCB, not the Nano onboard) should illuminate within a second. Open the serial monitor — you should see the "Quadruped ready" line.

Calibration

Every SG90 has a slightly different mechanical centre. With the firmware's default TRIM all at zero, your robot probably stands with one or two legs noticeably crooked. The calibration process derives the per-servo offset that makes the robot's neutral pose actually look neutral.

  1. Place the robot on a flat surface with all eight servos connected

    Apply battery power. The robot should be in its neutral pose. Observe which legs are off.

  2. Open the serial monitor

    Type s 0 90 and press send. Servo 0 (FL-H) should drive to its "neutral" angle. Visually compare to where you want the hip to be (femur horizontal, perpendicular to the body). If it's off by, say, +10° to one side, your trim for that servo should be –10.

  3. Try different angles to converge on the right trim

    Send s 0 85, s 0 95, etc., until the visual angle is correct. Note that adjustment value — that's the new TRIM[0].

  4. Repeat for all eight servos

    Servos 0, 2, 4, 6 are hips — should leave femurs horizontal. Servos 1, 3, 5, 7 are knees — should leave tibias vertical (hanging straight down).

  5. Update the TRIM array and re-upload

    Edit the int8_t TRIM[8] = { ... }; line in the sketch. Save. Re-upload. Disconnect battery first (as before).

  6. Verify the neutral pose

    Re-apply battery. The robot should now stand symmetrically. If not, repeat the per-servo trim adjustment for any that look off. Two iterations of calibration is normal; three means a servo or print has a real problem you should investigate.

Warning · Trim limits

Trim values larger than ±20° usually mean something is mechanically misaligned — typically a servo horn installed off-centre during assembly. Don't paper over a mechanical error in firmware. Power down, remove the horn, re-centre it physically, and start the calibration over.

What's in the Sketch — and What Isn't

The base sketch deliberately includes: servo init, neutral pose, one creep-forward gait, button toggle, serial single-servo command. It deliberately excludes: any sensor reading, any I²C, any communication beyond the USB serial, any autonomous behaviour beyond toggling the gait. The exclusions are there for a reason. We will populate them together when you arrive.
